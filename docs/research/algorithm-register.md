# Implemented algorithms and scientific boundaries

LaFA 0.1.0 implements the six requested families with explicit variants. The [single bibliography](../references.md) contains the original papers and source-review provenance. The [validation report](../validation.md) distinguishes numerical checks, finite-run experiments and outstanding GPU execution. Exa research remains outstanding under the approved primary-source fallback.

All potentials use `U = -log π`; a batch of states has shape `(chains, dimensions)` and a batched potential returns `(chains,)`. Float32 and float64 are supported. Specialized inference drivers use their stated ensemble, latent and observation axes. A finite interacting ensemble is not a collection of independent MCMC chains.

## Methods

Names below are public imports from the indicated module. All rows have executable implementations and CPU checks; CUDA cases are collected but have not yet run on a real GPU.

|---|---|---|
| `lafa.samplers.ULA` | `x' = x - h M ∇U + √(2hTM) ξ`; [R01, R02, R20](../references.md) | Constant positive diagonal mobility; finite-step bias. Analytic proposal/noise and Gaussian stationary covariance checks. |
| `lafa.samplers.MALA` | ULA proposal and full reverse/forward MH ratio; [R01, R19, R20](../references.md) | Fixed step, temperature and mobility; whole-chain acceptance. Ratio, rejection, invalid proposals and continuation checks. |

| `lafa.specialized.AnchoredLangevin` | Reference drift and noise scaled by `exp(U-U0)`; [R03](../references.md#r03) | Exact supplied reference potential, Euler discretization and random operational clock. | `lafa.samplers.KineticLangevin` | Euler–Maruyama for `dx=p/m dt`, `dp=-∇U dt-γp dt+√(2γmT)dW`; [R05, R06](../references.md) | Explicit Euler, not the exact frozen-force scheme analyzed in R06. Momentum and fluctuation–dissipation tests. |

The root imports `lafa.ULA`, `MALA`, `LipULA`, `LipMALA`, `BAOAB` are `torch.optim.Optimizer` adapters. Tensor-based drivers live in `lafa.samplers`. The optimizer MALA decision uses the complete parameter state; dynamic addition of parameter groups is explicitly unsupported. Closures must represent a deterministic full potential, with gradients recomputed on each call. Arbitrary sparse, complex or stateful models are not automatically supported.

## Computation and storage

For `N` states of dimension `D`, simple transitions retain O(ND) state and perform target/gradient work plus O(ND) arithmetic. Default step results own detached snapshots. Native `step(fields=...)` selects outputs and `advance(steps)` suppresses result allocations while retaining validation. Opt-in compiled potential/gradient evaluation has whole-sampler CPU timing evidence; eager validation can still synchronize CUDA. Chunked `ModulePotential` and optional vectorized function VJPs bound simultaneous transformed evaluations, without changing model or target definitions.

Exact pair methods cost O(N²D) arithmetic. Pair tiles use O(B² + BD) workspace and avoid a full N×N×D tensor. Matrix-free SVN avoids D×D Hessians but performs multiple HVPs and CG solves. pSVGD uses a thin SVD of the N×D likelihood-gradient matrix. Dense HOLA intentionally has a dimension guard; derivative providers must supply exact contractions and a Hessian spectral norm. SA-LEnKF retains a complete post-burn-in pool for a bounded number of stages, so memory depends on particles, dimension and per-stage budget. Birth/death rate recomputation prioritizes the specified sequential algorithm over a claim of fast large-N scaling.

The [recording guide](../api.md#recording-and-checkpoints) describes selected fields, stride, online moments, chunk readers and checkpoints. Tensor staging/queue memory is bounded; serialization overhead and manifest metadata are additional. GPU-to-host copies are currently synchronous, even when disk writing is asynchronous. None of the algorithms accumulates an unrequested trajectory.

## Diagnostics, fixtures and remaining extensions

`autocorrelation`, raw/bulk/tail ESS, `mcse_mean`, `mcse_quantile` and `rank_normalized_split_rhat` accept `(chains, draws, dimensions)` after warm-up. Raw ESS uses pooled Geyer positive/monotone sums and a conservative total-draw cap [R22]. Bulk ESS uses split rank normalization; tail ESS uses quantile indicators. Mean and quantile MCSE estimate finite-run variability. R-hat uses rank normalization, splitting and folding [R21]. New split ESS/MCSE APIs require at least 10 draws; undefined constant inputs yield NaN. `OnlineMoments` uses Welford's recurrence [R23]. These tools cannot establish convergence alone.

Fixtures include analytic Gaussians, a multimodal mixture, the supplied paper's normalizable Rosenbrock density, a normalized banana, actual sparse straight-ray 2D traveltime tomography, nonlinear transmission through a positive 2D field, a nonsmooth latent model and a linear Gaussian state-space model. The reduced nonlinear model has a refined two-coefficient quadrature reference. Separate full-grid experiments infer all 9/16 latent cells and compare with finite elliptical-slice references [R24], reporting reference mixing/MCSE and coverage across independent simulated datasets.

The initial implementation does not provide reflected anchored dynamics, finite-Monte-Carlo anchor estimation, full coupled SVN, arbitrary nonlinear-observation SA-LEnKF, approximate KSD pairs, distributed particles, fused CUDA kernels or general mixed-precision inference. These are extensions with separate derivation/performance requirements. Broader calibration, larger neural-network/full-grid problems and stronger reference mixing remain extensions beyond the measured small examples. Real GPU execution remains a release-validation gate, documented in [RunPod setup](../runpod.md).
