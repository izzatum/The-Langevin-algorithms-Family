# Executable tutorials

Run `python scripts/execute_notebooks.py --device cpu` from an environment with `pip install -e '.[notebooks]'`. Each notebook starts a clean kernel using the current Python executable, prints software/device/dtype/seed information, and writes its real outputs. Results are deterministic only within a compatible hardware/software stack. Notebook defaults use float64 and one CPU thread; `LAFA_DEVICE` selects the device and `LAFA_QUICK=0` increases budgets. The runner exposes these as `--device` and `--full`.

| Notebook | Experiment and independent reference | Interpretation |
|---|---|---|
| [01 Overdamped](../notebooks/01_overdamped.ipynb) | Correlated Gaussian moments and analytic ULA invariant covariance, followed by mixture and banana samples | MH correction, finite-step bias, acceptance and adaptation are separate properties. Frozen production discards adaptation. |
| [02 Inertial](../notebooks/02_inertial.ipynb) | Standard Gaussian position/momentum, autocorrelation and step sweeps; nonlinear dense HOLA smoke check | Equal iterations do not imply equal derivative cost. HOLA's analytic provider is exact for this fixture; dense derivatives are guarded. |
| [03 Specialized](../notebooks/03_specialized.ipynb) | Mixture temperature/noise schedules and corrected replica swaps; Normal/Laplace latent learning against integrated likelihood | Endpoint ensembles, a correlated cold-replica trace and shared-parameter learning have distinct sampling units and objectives. |
| [04 Stein particles](../notebooks/04_stein_particles.ipynb) | Rank-two likelihood in eight prior-whitened dimensions; polynomial prediction with an exact induced Gaussian reference | pSVGD freezes prior complements. SVN is block diagonal, with actual CG operator costs. Function transport uses an actual function map and destination VJP. |
| [05 KSD](../notebooks/05_ksd.ipynb) | Correct, shifted, overdispersed and mode-missing samples; signed U/V curves and timing by size | All ordered pairs are evaluated in blocks. Signed U can be negative, and low KSD can coexist with missed modes. |
| [06 Ensemble/hybrid](../notebooks/06_ensemble_hybrid.ipynb) | Repulsive/WFR ensembles; known-parameter filtering vs exact Kalman; separate SA parameter learning; nonlinear spatial inverse with refined quadrature | Finite ensembles and backward pools are approximations. The spatial reduced model has its own coefficient prior, and uncertainty is propagated through the nonlinear field map. |

The small budgets deliberately expose Monte Carlo variation and incomplete learning. Increasing iterations alone does not resolve poor geometry, missed modes, inappropriate bandwidths or a wrong target. Reference moments, trace plots, mode fractions and estimator assumptions should be checked together.

The generated [sampling](assets/overdamped.png) and [spatial uncertainty](assets/spatial-uncertainty.png) illustrations come directly from notebooks 1 and 6. Embedded notebook images are saved from those executions; no example plot is substituted for an algorithm result. Every scientific citation points to the consolidated [references](references.md), and the [algorithm register](research/algorithm-register.md) defines supported variants.

`--output /tmp/lafa-executed` preserves source notebooks while saving a second executed copy and `execution-results.json`. Failures preserve the notebook's underlying exception and return nonzero. An unavailable explicitly requested CUDA device is an error. The CPU results included in this checkout do not imply GPU validation.

For resources, run `python benchmarks/performance.py --device cpu --output /tmp/performance.json`. It measures actual sampler and pairwise particle work over bounded dimension/particle sweeps, then records off/synchronous/asynchronous/sparse modes including host staging and flush. Timings are local observations; noisy tiny workloads can reorder. CPU RSS is a process high-water mark, CUDA memory is allocated-tensor peak, and neither equals total device or system memory. Optional `--compile` checks eager/compiled agreement and times the pure ULA transition separately from full sampler work.

The included [CPU performance artifact](assets/performance-cpu.json) records the actual software stack and timings. In that run, the first functional ULA call including compiler/cache initialization took about 4.91 seconds; 60 warmed compiled calls took 0.00065 seconds versus 0.00114 seconds eager. Compiler caches were not cleared. These are pure transition calls with fixed input/noise tensors and exclude gradient evaluation, random-number generation, snapshots and recording. They are not a claim about end-to-end sampler acceleration.
