# Langevin Algorithms in PyTorch — LaFA

**Langevin algorithms** combine gradients of a target log density with random noise to explore a probability distribution. **The Langevin Algorithms Family (LaFA)** is a PyTorch research library implementing the **unadjusted Langevin algorithm (ULA)**, **Metropolis-adjusted Langevin algorithm (MALA)**, kinetic and adaptive methods, and related particle inference for Bayesian uncertainty quantification and inverse problems.

**Version:** 0.1.0 · **License:** MIT · **Python:** 3.11+ · **PyTorch:** 2.6+ · [Documentation](https://izzatum.github.io/The-Langevin-algorithms-Family/) · [Source repository](https://github.com/izzatum/The-Langevin-algorithms-Family)

Use optimizer-style samplers or explicit batched chains, record selected tensors in bounded chunks, and assess independent chains with R-hat, bulk/tail effective sample size (ESS) and Monte Carlo standard error (MCSE). Examples cover Gaussian and multimodal targets, neural networks, seismic tomography and nonlinear spatial inversion. Short experiments retain poor mixing and finite-reference uncertainty; see [validation evidence and limits](https://izzatum.github.io/The-Langevin-algorithms-Family/validation/).

```bash

cd The-Langevin-algorithms-Family
python -m venv .venv
source .venv/bin/activate
python -m pip install torch --index-url https://download.pytorch.org/whl/cpu
python -m pip install -e '.[test,notebooks]'
```

For CUDA, install the matching PyTorch wheel from [PyTorch's installer](https://pytorch.org/get-started/locally/) before installing LaFA. Move the target, state and generator to the same device. The tutorial runner requires an available GPU when `--device cuda` is requested and never silently falls back to CPU. GPU performance depends on workload; small problems may be faster on CPU.

## Sample with an optimizer-like interface

The root `lafa.MALA` adapter accepts PyTorch parameters and a repeatable potential closure. The potential is a scalar **negative log density**, not a loss averaged over changing minibatches.

```python
import torch
import lafa

x = torch.nn.Parameter(torch.zeros(2, dtype=torch.float64))
sampler = lafa.MALA([x], lr=0.1,
                    generator=torch.Generator().manual_seed(7))

def closure():
    sampler.zero_grad()
    potential = x.square().sum() / 2
    potential.backward()
    return potential

for _ in range(200):
    sampler.step(closure)
print(x.detach())
```

Freeze dropout, changing buffers and stochastic data operations in corrected closures. A sampler cannot make an arbitrary mutable model into a deterministic target.

For batches of independent chains, use the explicit state API:

```python
from lafa.samplers import MALA
from lafa.problems import Gaussian

target = Gaussian([0., 0.], [[1., 0.5], [0.5, 1.]])
chain = MALA(target, torch.zeros(32, 2, dtype=torch.float64),
             step_size=0.1, generator=torch.Generator().manual_seed(7))
chain.advance(200)  # warm-up without result snapshots
result = chain.step(fields=('position', 'accepted'))
print(result['position'].shape, result['accepted'].float().mean())
```

## Record only what you need

Samplers keep current state rather than a growing trajectory. Record selected tensor fields at a chosen stride; position gradients, particle update directions and function gradients have different meanings, so label the tensor you supply explicitly.

```python
from tempfile import TemporaryDirectory
from lafa.recording import Recorder, TraceReader

with TemporaryDirectory() as folder:
    with Recorder(folder, fields=['position'], every=10,
                  chunk_size=8, max_buffer_bytes=1024 * 1024) as trace:
        for step in range(100):
            if step % 10 == 0:
                trace.record(step, **chain.step(fields=('position',)))
            else:
                chain.step(fields=())
    saved = TraceReader(folder).read('position')
    print(saved.shape)  # (10, 32, 2), stored on CPU
```

Use `TraceReader` iteration to process chunks without loading a whole trace. `async_write=True` overlaps disk writing with computation; device-to-host staging still costs time. Closing or flushing is the persistence boundary. `OnlineMoments` supports summaries without retaining draws. Sampler checkpoints are separate from traces and require the same target and compatible device to continue exactly.

## Frequently asked questions

**What is the difference between ULA and MALA?** ULA accepts every gradient-plus-noise update and generally has finite-step bias. MALA adds a Metropolis–Hastings acceptance step using both proposal densities. A valid fixed MALA kernel preserves its target, but a finite run still needs mixing checks. See the [algorithm guide](https://izzatum.github.io/The-Langevin-algorithms-Family/langevin-algorithms/) and sources [R01](https://izzatum.github.io/The-Langevin-algorithms-Family/references/#r01), [R19](https://izzatum.github.io/The-Langevin-algorithms-Family/references/#r19), [R20](https://izzatum.github.io/The-Langevin-algorithms-Family/references/#r20).

**Can I use LaFA like a PyTorch optimizer?** Yes. Root classes such as `lafa.MALA` accept `torch.nn.Parameter` objects and a closure. Batched chains use `lafa.samplers`; interacting particles and filtering have explicit drivers for their different state and objectives.

**Can I use a PyTorch neural network as a target?** Yes. `ModulePotential` evaluates flattened model states with loop or chunked `vmap`; function-space methods can batch their VJPs. Add the prior explicitly and use a deterministic full-data likelihood. [Tutorial 4](https://izzatum.github.io/The-Langevin-algorithms-Family/notebooks/04_stein_particles/) shows the API.

**Does LaFA run on GPUs?** Its numerical methods use native PyTorch tensor operations and explicit CUDA devices. GPU tests and a bounded RunPod runner are provided; real GPU validation has not yet completed. CPU results are not evidence of GPU performance.

**Are all outputs exact posterior samples?** No. Fixed-kernel MALA applies a Metropolis correction, but finite runs still require convergence checks. ULA has step bias; continuously adaptive methods and finite interacting ensembles have additional approximation limits. KSD is a diagnostic, not a sampler or a convergence guarantee.

**Does LaFA implement stochastic gradient Langevin dynamics (SGLD)?** No dedicated SGLD sampler is implemented. The documented MALA targets require a deterministic full-data potential; replacing it with changing minibatches is not a supported MALA approximation.

**Can I save samples and gradients without retaining the full trajectory in RAM?** Yes. `Recorder` writes selected detached tensor fields in bounded chunks; `TraceReader` streams them, and `OnlineMoments` retains only summaries. Recording costs transfer and disk bandwidth.
